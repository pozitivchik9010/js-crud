# 🚀 Інструкція з деплою на безкоштовні хостинги

Цей додаток можна задеплоїти на декілька безкоштовних хостингів. Нижче детальні інструкції для кожного з них.

## 📋 Підготовка перед деплоєм

### 1. Перевірте .gitignore
Переконайтеся, що `.env` та `node_modules/` додані до `.gitignore`:
```
node_modules/
.env
```

### 2. Оновіть package.json
Переконайтеся, що у вас є правильний скрипт `start`:
```json
"scripts": {
  "start": "node ./index.js"
}
```

### 3. Створіть Git репозиторій
```bash
git init
git add .
git commit -m "Initial commit"
```

### 4. Завантажте код на GitHub
```bash
git remote add origin https://github.com/ВАШ_USERNAME/ВАШ_РЕПОЗИТОРІЙ.git
git branch -M main
git push -u origin main
```

## 🟢 Варіант 1: Render.com (Рекомендовано)

### Переваги:
- ✅ Безкоштовний план
- ✅ Автоматичні деплої з GitHub
- ✅ HTTPS з коробки
- ✅ Простий у використанні
- ⚠️ Засинає після 15 хвилин неактивності (перший запит може бути повільним)

### Кроки:
1. Зареєструйтеся на [render.com](https://render.com)
2. Натисніть **"New +"** → **"Web Service"**
3. Підключіть ваш GitHub репозиторій
4. Налаштуйте параметри:
   - **Name**: `js-crud-app` (або будь-яка назва)
   - **Environment**: `Node`
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Plan**: `Free`
5. Додайте Environment Variables:
   - `NODE_ENV` = `production`
   - Додайте інші змінні з вашого `.env` файлу
6. Натисніть **"Create Web Service"**
7. Зачекайте 3-5 хвилин на деплой

### Використання конфігураційного файлу:
Файл `render.yaml` вже створений. Render автоматично його знайде.

- ✅ Не засинає

5. Додайте Environment Variables у вкладці **"Variables"**:

   - `PORT` = (Railway автоматично встановить)
   - Додайте інші змінні з вашого `.env`
6. Натисніть **"Deploy"**
7. Перейдіть у **"Settings"** → **"Networking"** → **"Generate Domain"**

### Використання конфігураційного файлу:
Файл `.Railway` вже створений. Railway автоматично його використає.

## 🔴 Варіант 5: Fly.io

### Переваги:
- ✅ Безкоштовні ресурси (3 GB persistent volume)
- ✅ Не засинає
- ✅ Можливість розгортання по всьому світу

### Кроки:
1. Встановіть Fly CLI:
   ```bash
   powershell -Command "iwr https://fly.io/install.ps1 -useb | iex"
   ```
2. Зареєструйтеся та увійдіть:
   ```bash
   fly auth signup
   fly auth login
   ```
3. Запустіть деплой з кореневої папки проекту:
   ```bash
   fly launch
   ```
4. Відповідайте на питання:
   - App name: натисніть Enter (автоматично згенерується)
   - Region: виберіть найближчий регіон
   - Database: No
   - Deploy: Yes
5. Додайте secrets (змінні оточення):
   ```bash
   fly secrets set NODE_ENV=production
   ```

## 🛠️ Загальні поради

### 1. Environment Variables
Не забудьте додати всі змінні з вашого `.env` файлу на хостингу.

### 2. PORT
Більшість хостингів автоматично встановлюють змінну `PORT`. Ваш код вже це підтримує:
```javascript
const port = normalizePort(process.env.PORT || '3000')
```

### 3. NODE_ENV
Встановіть `NODE_ENV=production` для продакшн оточення.

### 4. Перевірка після деплою
- Відкрийте URL вашого додатку
- Перевірте всі маршрути
- Перевірте консоль браузера на помилки
- Перевірте логи на хостингу

### 5. Автоматичні оновлення
Всі ці хостинги підтримують автоматичний деплой при push у GitHub:
- При push у `main` гілку → автоматичний деплой

## 📝 Troubleshooting

### Проблема: "Application failed to start"
**Рішення**: Перевірте логи та переконайтеся, що:
- Всі залежності встановлені
- `npm start` працює локально
- Environment variables встановлені

### Проблема: Static файли не завантажуються
**Рішення**: 
- Переконайтеся, що папка `public` не в `.gitignore`
- Перевірте шляхи до статичних файлів

### Проблема: 502 Bad Gateway
**Рішення**:
- Перевірте, що додаток слухає правильний порт
- Перевірте логи на хостингу
